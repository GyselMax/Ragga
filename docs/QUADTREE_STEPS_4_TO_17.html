What

isFarEnough checks the few nodes within 40 instead of every node in the graph. Each accepted node goes into the tree straight away, so the next candidate can see it.

Why

The bounds check comes first so thrown-away candidates don't cost a search. isFarEnough itself doesn't change: it already takes a Collection<Node>. A node exactly 40 away is returned (the tree uses ≤) and still accepted (isFarEnough uses <), the same as today.

If wrong

Without index.insert(candidate), the tree only ever holds the starter, so nearly every candidate passes. Measured: the node phase runs away, past 20,000 nodes and still growing, where it should stop at 326.

What

Instead of every street in the city, it tests the streets attached to nodes within 240 of a.

Why

Every street is at most 120 long, so any street that could cross a→b has both ends within 240 of a. That's the proof in QUADTREE_CHANGE1.html. A street can turn up twice, once from each end, which is harmless; change 1 removes that later.

If wrong

Measured with 120 instead of 240: seed 67 and the 9-starter city still came out with 0 crossing streets. So 240 isn't something these cities needed. It's the radius that's guaranteed to catch every crossing, so keep 2 * EDGE_SEARCH_RADIUS, tied to the constant.
