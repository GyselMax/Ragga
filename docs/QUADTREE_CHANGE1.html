What happens now

One street step, the same search over and over

With the Q21 wiring, a step looks at every node within 120 of current. Each candidate that passes the cheap checks (degree, duplicate, triangle, angle) reaches isCrossingFree, and that method searches 240 around current again.

Q21 wiring: runs again for every candidate

// growStreet: for every candidate within 120 …
if (!passesEdgeConstraints(graph, tree, current, candidate)) continue;

// isCrossingFree(graph, tree, a, b): … a is always current
for (Node node : tree.findWithin(a.getX(), a.getY(),
                                 2 * EDGE_SEARCH_RADIUS)) {
    for (DefaultEdge edge : graph.edgesOf(node)) {
        // test a→b against the street
    }
}

Why it's safe

The answer doesn't depend on the candidate

Two facts make one list per step enough:

  • The search circle sits around a only. The candidate b is used only in the line test itself, never to choose which streets to look at.
  • Nothing changes during a step. graph.addEdge runs after the candidate loop, so every candidate sees the same streets.
  1. Every street is at most 120 long, because growStreet only steps to nodes within EDGE_SEARCH_RADIUS. The new street a→b is too.
  2. If c–d crosses a→b at P, then P lies on both streets: |aP| ≤ 120, |cP| ≤ 120 and |dP| ≤ 120.
  3. So |ac| ≤ |aP| + |Pc| ≤ 240, and the same for d. Both ends of any street that could cross are inside the circle.
  4. Each such street turns up from both its ends, so taking it only from one end loses nothing.

Keep the radius tied to the street length

Write the radius as 2 * EDGE_SEARCH_RADIUS, not 240. If streets ever get longer than the search radius (for example, roads added later for lots), the radius becomes EDGE_SEARCH_RADIUS plus the longest street.

How to build it

Four steps, once the Q21 wiring is in

  1. Split the crossing check off the other constraints

    passesEdgeConstraints

    Keep degree, duplicate, triangle and angle together (for example as passesCheapConstraints), and call the crossing check separately from growStreet. The crossing check stays last, so it still runs only for candidates that pass everything else.

  2. One list per step, filled on first need

    growStreet, inside while (true)

    List<DefaultEdge> nearbyStreets = null;   // new for every step
for (Node candidate : tree.findWithin(current.getX(), current.getY(),
                                      EDGE_SEARCH_RADIUS)) {
    if (candidate == current) continue;
    if (!passesCheapConstraints(graph, current, candidate)) continue;
    if (nearbyStreets == null)
        nearbyStreets = findNearbyStreets(graph, tree, current);
    if (!isCrossingFree(nearbyStreets, graph, current, candidate))
        continue;
    // … scoring unchanged
}

    Use a local variable, not a field: GraphGenerator is a Spring singleton, and a local can't leak from one step into the next.

  3. Collect the nearby streets, each once

    new: findNearbyStreets(graph, tree, a)

    Search 2 * EDGE_SEARCH_RADIUS around a, loop graph.edgesOf(node) for every node found, and keep a street only when node == graph.getEdgeSource(edge). That's the "take it from one end" rule from the proof.

  4. Test against the list

    isCrossingFree(streets, graph, a, b)

    The same body as today, but it loops over the given list instead of graph.edgeSet(). It still skips streets that share an end with a or b, and still uses Line2D.linesIntersect.

The last bar is why the list is filled on first need. Many steps end before any candidate reaches the crossing check, for example when current already has four streets. Searching at the start of every step does that work anyway and is 26% slower.

How to check it

Same seed, same streets, in the same order

  • Seed 67 must still give 326 nodes and 549 streets.
  • Counts can match by luck, so compare the streets too: write every street's two end coordinates in graph.edgeSet() order to a file before and after the change, and diff the two files.

On JGraphT

Change 1 is plain geometry and works with any graph library, which is why it's first. Changes 2–4 are parked, since they're about JGraphT. One correction: JGraphT doesn't draw graph.png. drawGraph does that with Java2D, and JGraphT is the data structure holding the nodes and streets. If it stays as that, change 4 (SimpleGraph) is still a free 11–14%.
