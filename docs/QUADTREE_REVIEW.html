Real bugs

Two bugs, one of them already breaks searches

1 · The builder's skip test compares the circle with itself breaks search

QuadTreeBuilder.java:39–40

The parameters x, y hide the fields x, y, so every x here is the circle's centre. dx is always 0, and line 40 checks y against the x edges. Whole squares get skipped even though they hold matching nodes.

Now

double dx = x - Math.clamp(x, x, x + size);
double dy = y - Math.clamp(y, x, x + size);

Fix

double dx = x - Math.clamp(x, this.x, this.x + size);
double dy = y - Math.clamp(y, this.y, this.y + size);
wrong on ~50% of searches circle (1372, 45) r 266: 16 nodes expected, 0 found seed 67 with this builder: >20,000 nodes instead of 326

2 · QuadTree still has no findWithin blocks wiring

QuadTree.java:15

The planned growStreet and isCrossingFree call tree.findWithin(…), so they won't compile until it exists. Nothing breaks today. Your QuadSquare already has a default findWithin, so the body can pass the call on to root.

Worth changing

Three things that aren't broken today

Nodes outside the root square are silently lost latent

QuadTreeBuilder.java:20

insert doesn't check bounds, so such a node lands in an edge child and every search skips it. Tested: (-10, -10) in a 0..100 tree isn't found at its own position. Safe today because isWithinBounds runs first.

Suggestion: throw an exception for such nodes, or state the rule in the comment.

The fields share their names with the circle centre caused bug 1

QuadTreeBuilder.java:9

In the records the corner is x(), so the names can't clash. In the builder a bare x means the parameter.

Suggestion: rename them to minX, minY as Q21 does, or write this. wherever a method also has x/y parameters.

The exception has no serialVersionUID lint only

BranchDoesNotHave4ChildrenException.java:3

The only -Xlint:all warning in the package. Harmless.

Suggestion: a wrong child count is a bad argument, so extending IllegalArgumentException would also fit.
