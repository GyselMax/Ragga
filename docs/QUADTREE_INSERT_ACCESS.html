Why the inside calls look private

private means "this class", not "this object"

  • At line 22, one builder calls insert on another builder, its child. That's allowed with private, because the calling code is written inside QuadTreeBuilder.
  • You already rely on this: freeze is private, and line 76 calls child.freeze(leaves) on each child.
  • So the recursion alone would be fine with private. The call at GraphGenerator.java:69 is the one that needs public.

Why not package-private

Java packages don't nest, so the parent package can't see it

  • Leaving the modifier out makes insert visible only inside be.magycks.ragga.generation.quadtree.
  • GraphGenerator is in be.magycks.ragga.generation. The names look like parent and child, but to the compiler they are two unrelated packages, so this fails with the same kind of error.

Why the builder needs it at all

Nodes go in one at a time while the city grows

In step 5, each candidate is checked against every node placed before it, so it has to be in the index before the next candidate is drawn. A constructor that takes all the nodes at once can't do that, because they don't exist yet. That's why there are two classes: the builder takes insert calls while the city grows, and build() hands the street phase a frozen tree with no insert at all.

The idea

A method's access shows who is allowed to call it. insert is how the builder gets filled, so the code that fills it has to be able to reach it. split, freeze and ChildWithNode are steps inside insert and build, and they are already private.
