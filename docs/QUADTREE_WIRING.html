The draft window

What the draft draws, and its keys

  • Nodes appear one by one during the node phase. The newest is orange.
  • Quadtree leaves appear once the tree is frozen.
  • Streets, with the newest in orange.
  • The node the street is growing from, with its 120 search circle.
KeyDoes
SpacePause and resume. Generation waits while paused.
+ / −Speed from ×⅛ to ×8, then "max" (no waiting).
QShow or hide the quadtree squares.
closeGeneration finishes at full speed, and graph.png is still written.

Part A

Quadtree (Q21)

Do these first and check that seed 67 still gives 326 nodes and 549 streets before starting part B.

Eight steps

From the builder in run() to the crossing check

  1. Give QuadTree its findWithin

    QuadTree.java:15, above collectWithin

    It returns a new list each call. QuadSquare already has a default findWithin, so the body can hand the call on to root.

  2. Imports

    GraphGenerator.java:3

    be.magycks.ragga.generation.quadtree.QuadTree and …quadtree.QuadTreeBuilder.

  3. Create the builder and insert the starters

    run(), before the seed loop at :65

    QuadTreeBuilder index =
        new QuadTreeBuilder(0, 0, Math.max(GRID_WIDTH, GRID_HEIGHT));
for (Node seed : seeds) {
    graph.addVertex(seed);
    index.insert(seed);
    pending.add(seed);
}

  4. Pass the builder to the node phase

    run():73 and generateClusteredNodes:99

    Add an index parameter, the same way graph is passed.

  5. Check nearby nodes only, and keep the tree in step

    generateClusteredNodes:127–130

    if (!isWithinBounds(candidate)) continue;
List<Node> nearby =
        index.findWithin(candidateX, candidateY, NODE_MINIMUM_DISTANCE);
// was graph.vertexSet()
if (isFarEnough(candidate, nearby, NODE_MINIMUM_DISTANCE)) {
    graph.addVertex(candidate);
    index.insert(candidate);   // every addVertex needs one
    generatedNodes.add(candidate);
}

  6. Freeze once, then hand the tree to the street phase

    run():87, generateEdges:161 and :167

    QuadTree tree = index.build(); right after the growth loop, then generateEdges(graph, random, tree), which passes tree to growStreet.

  7. Step only to nodes within reach

    growStreet:180–182, and isWithinSearchRadius:225

    Loop over tree.findWithin(current.getX(), current.getY(), EDGE_SEARCH_RADIUS) instead of graph.vertexSet(). The isWithinSearchRadius line and method can go, since the tree already checked that distance.

  8. Test only the streets that could cross

    passesEdgeConstraints:234/239 and isCrossingFree:243–244

    Pass tree through. In isCrossingFree, loop over tree.findWithin(a.getX(), a.getY(), 2 * EDGE_SEARCH_RADIUS), and for each of those nodes over graph.edgesOf(node). The rest of the body stays the same.

Then change 1 fits on top

Step 8 is exactly where change 1 (QUADTREE_CHANGE1.html) goes later: the same search, done once per street step.

Part B · draft

Live view

Nothing here exists in your project yet. Steps 9–11 set the window up, and steps 12–17 are one-liners in GraphGenerator. The view is a field, so it doesn't need passing through every method.

Nine steps

Set the window up, then report progress from five places

  1. Add the window class

    new: generation/view/LiveCityView.java

    The draft in docs/examples/ handles the drawing, the pacing and the keys, and its hooks do nothing when the view is off. Write your own, or start from it. It only needs Node and QuadTree.

  2. Let Spring open windows

    RaggaApplication.main

    SpringApplication app = new SpringApplication(RaggaApplication.class);
app.setHeadless(false);   // Spring runs headless by default
app.run(args);

  3. Add the settings

    application.properties, after EDGE_SEARCH_RADIUS

    LIVE_VIEW_ENABLED=true
LIVE_VIEW_MS_PER_NODE=6
LIVE_VIEW_MS_PER_STREET=4

  4. Settings and the view field

    next to the other @Value fields, after :42

    @Value("${LIVE_VIEW_ENABLED}")
private boolean LIVE_VIEW_ENABLED;
@Value("${LIVE_VIEW_MS_PER_NODE}")
private double LIVE_VIEW_MS_PER_NODE;
@Value("${LIVE_VIEW_MS_PER_STREET}")
private double LIVE_VIEW_MS_PER_STREET;
// import be.magycks.ragga.generation.view.LiveCityView
private LiveCityView view = LiveCityView.NONE;

  5. Open it at the start of run()

    run(), before :52

    view = LiveCityView.open(LIVE_VIEW_ENABLED, GRID_WIDTH, GRID_HEIGHT,
        LIVE_VIEW_MS_PER_NODE, LIVE_VIEW_MS_PER_STREET);

  6. Report every node

    the seed loop at :65, and after graph.addVertex(candidate)

    view.nodeAdded(seed) and view.nodeAdded(candidate).

  7. Show the frozen tree

    right after index.build() from step 6

    view.treeBuilt(tree)

  8. Follow the street as it grows

    growStreet: top of while (true) at :176, and after graph.addEdge at :194

    view.stepAt(current, EDGE_SEARCH_RADIUS) at the top of each step, and view.streetAdded(current, best) after the edge is added.

  9. Say it's finished

    run(), after generateEdges

    view.done()

If the window doesn't open

With the draft class, the console says live view skipped: Java is running headless when step 10 is missing or something else forces headless mode, such as a -Djava.awt.headless=true flag in the IntelliJ run configuration.
